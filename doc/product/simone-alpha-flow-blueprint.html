SimOne Alpha Product Flow Blueprint

A reviewable behavior map for the first coherent SimOne experience: landing, sign-in, messy venture intake, guided draft, SIM map, Sprint Zero review, diagnosis, and next action. The default user is Thomasina, so provider and adapter complexity stays out of the first path.

North Star

Useful Output First

SimOne should produce a first map, bottleneck, or brief before asking the user to understand SIM theory.

Human Judgment Stays Visible

The user approves public, customer, financial, governance, deletion, cross-engine, and spend-policy boundaries.

Audit Before Experiments

Dev mode routes through inspectable records. Fusion, Fugu, and external Headroom are experiment lanes after the sovereign spine works.

Primary Journey

This is the target alpha path. It intentionally starts with a protected workspace and messy input, not manual engine setup.

1. LandingPromise: understand and improve the venture system.Primary action: start protected workspace.
2. Sign InProtect work before capture.Anonymous scanner can hand off safely.
3. Venture IntakeUser writes messy context, imports notes, or names a customer signal.
4. Guided DraftSimOne drafts map, assumptions, and missing evidence.
5. SIM MapEngines and drivers appear as plain operating areas.
6. Sprint ZeroBrief asks for approval before tasks or agents run.
7. DiagnosisScanner and Coach explain the bottleneck and boundary.
8. Next ActionUser chooses: save, share, delegate, ask why, or revise.

Incomplete Data Behavior

When the user gives too little context

  • Show a partial map.
  • Name the missing evidence.
  • Ask one high-leverage question.
  • Avoid fake confidence scores.

When live integrations are unavailable

  • Show the unavailable state plainly.
  • Do not invent Customer Engine status.
  • Keep prior saved wiki synthesis separate from live bridge data.
  • Offer manual input or retry.

When a decision crosses a boundary

  • Pause before public, customer, cash, deletion, governance, cross-engine, or spend-policy changes.
  • Explain the boundary in plain language.
  • Let the user approve, edit, or decline.

When model routing is uncertain

  • Record the route decision.
  • Use the conservative lane.
  • Escalate to Fusion only for high-risk disagreement.
  • Use Fugu only as a bounded specialist experiment.
